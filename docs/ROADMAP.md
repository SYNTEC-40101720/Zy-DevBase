# DevBase 路线图

模板能力的演进计划。每项含触发条件——不满足触发条件就不做，保持模板精简。

- 后端分层骨架（domain / application / api / desktop）稳定，测试基线见下方验收记录
- 桌面壳稳定；更新简化为用户手动检查版本、提示并打开发布页，不含下载/替换/回滚/独立 updater

- CI：GitHub Actions 跑后端 pytest（3.12/3.13）+ 前端 typecheck/test/build + 版本一致性检查

## 已评估、暂不做

### 任务持久化（SQLite/JSON 落盘）

**结论：等第一个派生项目提出需求再做。**

- 当前边界"任务状态进程重启即丢"对模板本身够用——演示任务只验证运行时契约
- 桌面工具的任务历史需求形态各异（审计日志？断点续跑？仅展示?），先做大概率返工
- 若做：在 `application` 层加 `JobStore` 端口（对齐 `ProgressSink` 的端口模式），内存实现为默认，SQLite 实现为可选依赖，不破坏现有测试

**触发条件**：某派生项目需要跨会话任务记录，且第二个项目也需要同样的形态。

### 多任务并发运行时

**结论：等批量处理类工具真实出现再做。**

- 单任务模型让"取消/冲突检测/事件重放"都简单可靠；多任务会牵动事件总线、
  WebSocket 快照结构（当前以"当前任务"为权威）、前端 BottomPanel 事件流
- 若做：`_active: _MutableJob` → 任务表 + 每任务取消事件，API 层增 `job_id` 路径参数；
  `/jobs/current` 保留为兼容别名

**触发条件**：某派生项目需要同时跑 ≥2 个后台任务（而非排队串行即可满足）。

## 近期事项

### 更新策略简化

GitHub 连接不稳定，而模板服务于轻量本地工具，因此取消完整自更新系统。只在用户主动点击时读取版本元数据，提供发布页链接；不下载、替换、回滚或自重启。旧的路由重写草稿 stash 保留为历史参考，不应再直接应用。

本次修改仅作用于 Zy-DevBase 模板，不批量变更已派生的 Modbus 等应用。

验收记录（2026-10-16）：后端 pytest 153 项通过（1 条第三方 Starlette 弃用警告）；前端 typecheck、Vitest 7 项和生产构建通过；版本一致性检查和打包预检通过。PR #12 合并后 GitHub Actions 的前端、Python 3.12/3.13、版本一致性全部通过；v0.3.8 打包及 Release 完成，资产与 GitHub SHA-256 一致。浏览器对新版本提示、离线提示、无需更新完成实操；冻结程序 API 版本与只读路由已验，模拟响应覆盖各提示状态。实际 WebView2 窗口关闭后的 exit 0 和端口释放尚未验收，不宣称通过。
